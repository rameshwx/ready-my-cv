# Evaluation methodology

Twenty synthetic cases cover eleven roles, strong/weak/list-only/missing evidence, approved aliases, partial-match resistance and keyword stuffing. Gold labels live in `evaluation/datasets/cases.json` separately from produced output. The baseline performs bounded exact canonical-term scoring; the final workflow uses boundaries, approved aliases, sections and action context. Every case, failure, runtime and zero cost is reported. The client and server use the same compiled Dart workflow; the server runner accepts structured parsed-document fixtures over private stdin/stdout and returns only verified result JSON. The runners write JSON, trajectories and a Markdown comparison into `evaluation/output/`.

The current generated run verifies 20 cases and 100 requirement labels: macro-F1 0.800, evidence traceability 1.000, repeat-run consistency 1.000, zero failed cases, and average runtime about 2.25 ms on the local fixture runner. The contradictory class has no positive gold examples in this fixture set, so its F1 is not a meaningful production estimate.
